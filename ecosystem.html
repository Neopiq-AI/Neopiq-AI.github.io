Ecosystem · Microsoft · ServiceNow · partners and channel

One ChatAdmin, reachable through the ecosystems you already use — labelled by what exists today

ChatAdmin administers Microsoft Azure, Microsoft Entra, Microsoft 365 and Microsoft Power Platform. It is designed as one reasoning-and-execution engine that can be acquired, accessed, embedded or invoked through different channels rather than as a different product per channel. Every item on this page carries one of three labels, and no logo appears for a relationship that does not formally exist.

available now built, tested, in the product · in development code exists, tested, not live · planned designed and written down, not built

Microsoft

ChatAdmin is Microsoft-native by construction: it operates through Microsoft Graph, Azure Resource Manager, the Exchange Online administration endpoint and the Power Platform administration APIs, with identities that live in the Microsoft tenant it administers. Neopiq is an independent software vendor and is not affiliated with, endorsed by, or sponsored by Microsoft.

ServiceNow

ChatAdmin does not replace ServiceNow, and connecting a ticketing system to Microsoft is not in itself unique. The division of work we are designing for: ServiceNow owns the service-management process — requests, tickets, workflow, assignment, escalation, organisational state. ChatAdmin understands incomplete Microsoft intent, inspects the real Microsoft state, reasons across the Microsoft areas, prepares the operational plan, identifies the missing decisions, presents a meaningful approval, executes the authorised change and verifies the outcome — the Microsoft reasoning-and-execution layer a workflow invokes.

One engine, many doors

Whichever route a customer arrives by — this website, Microsoft Marketplace, an MSP, a distributor, a ServiceNow workflow — the same ChatAdmin engine does the Microsoft work: the same reads, the same cards, the same ceilings, the same verification. Channels differ in acquisition, identity, provisioning, entitlement, packaging, tenant binding and the surrounding user experience, never in the reasoning-and-execution core, and the core is never made dependent on one partner.
