Documentation: enough to use both products without asking us anything

Two products, two halves of this page. The Planning Data Auditor for Microsoft Dynamics 365 Supply Chain Management is the free browser check of planning settings and master data — its half covers what it checks, the extracts it needs, how to run it, and how to read a finding. ChatAdmin administers Microsoft Azure by conversation — its half covers what it can manage and exactly what the approval gate does. Where documentation does not exist yet, this page says so instead of linking to it.

Planning Data Auditor

Free · runs in your browser · nothing uploaded

A rules-and-arithmetic check over extracts of your Dynamics 365 planning and master data. Deterministic: same input, same output, every time. No account, no upload, no model guessing.

What it checks

26 checks over 11 extracts of planning and master data, asking three kinds of question in increasing order of inference:

  • Is it filled in? Active planning items missing lead times, suppliers, planners, sites, coverage groups.
  • Do the records agree with each other? Item lead times contradicting vendor records, references to things that no longer exist, manufactured items without routes.
  • Does the setting match reality? Configured lead time against actual receipts, safety stock against demand volatility, forecast against real order intake, service performance against its own past.

Seven kinds of comparison carry those questions: missing values, missing owners, cross-table conflicts, outliers against peers, configuration against history, service measures getting worse, and behaviour drifting from its own past.

The extracts it needs

Eleven extracts, shaped like Dynamics 365 planning and master-data tables, produced by you as CSV files — the tool never connects to your system. The authoritative list of extracts and required columns is inside the tool itself, which is deliberate: the tool and its input specification cannot drift apart. Load what you have; any check your extracts cannot answer is reported as not-run, with the reason — never silently skipped.

Synthetic sample data ships with the tool, so you can see complete, worked findings before preparing a single extract of your own.

How to run it

  • Open the free check in a current browser. Nothing to install, no account to create.
  • If you want proof of the privacy property first: open your browser’s network tab, or disconnect from the network entirely once the page is loaded. The check runs the same either way.
  • Load your CSV extracts — or one click loads the synthetic sample data.
  • Run the checks and read the findings in the same tab. Nothing is stored between runs; closing the tab clears everything.
How to read a finding

One problem, one named object, evidence attached

Every finding carries the same fields, in planning language:

  • What is wrong, in one sentence, and which objects — item, vendor, site — with who owns it
  • The evidence: configured value, observed value, sample size, threshold crossed
  • What it costs you, the likely cause, and what to change — an action, not “investigate”
  • Where it came from: the tables and files read
  • How sure we are — a confidence figure that is stated judgement, not a measured probability, with the arithmetic shown

Findings are hypotheses with evidence, built to be overruled in ten seconds by a human who knows the business reason. Thresholds live in plain rule files so you can argue with them. The deeper treatment is on how it works.

ChatAdmin

No self-service sign-up today · access starts with a conversation

ChatAdmin turns a conversation into enumerated operations against Azure — and stops before every change until a person approves it.

What it can manage

Resource groups, storage accounts, key vaults, virtual networks, Linux virtual machines, Log Analytics workspaces, and Container Apps environments and apps — create-or-update only, with read-only listing of what exists. No capability deletes anything today, and the things it refuses outright — credential creation, secret disclosure, non-Azure endpoints — are refused before any call is attempted.

The approval gate, step by step

What you see before anything changes

  • You ask for something in plain language; the agent proposes a specific operation.
  • If it would change Azure, a card appears: the action name, every parameter (passwords and keys masked), and the target subscription.
  • You click Approve or Reject. The agent waits — it cannot proceed on its own.
  • Five minutes of silence declines the action automatically. A decline is final for that request; the agent does not retry unless asked.
  • Read-only questions — what resource groups exist, what is in one — run without a card.

Every action lands in a structured audit trail: timestamp, operation, target resource, result, secrets redacted. Its current limits are stated on the permissions page, including that it does not yet record which human approved — and that the operator’s own terminal interface, unlike the browser flow described here, has an explicit auto-approve flag.

Documentation that does not exist yet

So this page cannot over-promise by omission: there is no downloadable manual for either product, no administrator guide for ChatAdmin beyond this page and the permissions page, and no API reference — because there is no public API. There are no integration guides, because the Planning Data Auditor deliberately integrates with nothing and ChatAdmin is not yet open for sign-up. A written explanation of each individual check in the Planning Data Auditor exists only in the form the tool itself shows: the finding, its evidence, and its thresholds.

When one of these gaps closes, the material will be linked from this page. Until then, a question this page does not answer goes to support@neopiq.ai — hours and the response target are on the support page.
