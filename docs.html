Documentation: enough to use ChatAdmin without asking us anything

ChatAdmin administers Microsoft Azure, Microsoft Entra, Microsoft 365 and Microsoft Power Platform by conversation. This page covers what you can ask in each area, what a card contains, what a result looks like, what is recorded, and the documentation that does not exist yet — stated here instead of linked to.

Using the chat

The header

Names the environment ChatAdmin is connected to and the identity it acts with in each area, whether each area is live or simulated, and whether the language model is ready. Read it before you type.

Asking

Plain words, your own names. Reads answer in seconds and need no approval. If a detail materially affects the operation and cannot be read from the environment, ChatAdmin asks one question instead of guessing; otherwise it proposes the obvious choice and says so on the card.

The approver key

The first time you click Approve on an area’s card, the page asks for that area’s key, sent to you on a different channel than the link. It stays in that browser tab only. Never type it into the chat box.

Sessions

Your conversation lives in the tab while you use it and is cleared when you start over or after a few hours idle. Each tab is its own session. The transcript is kept separately, with secrets removed.

Cards and plan cards

  • A card shows the area, the environment, the action and every parameter (secrets masked), a preview when one exists, and a five-minute countdown.
  • A plan card lists up to twelve steps behind one approval; one Approve runs them in order with no further cards, stopping at the first error.
  • Approve runs the change; the result is read back and shown as “Verified after change”. Reject stops it; ChatAdmin does not retry unless asked. No click within five minutes counts as a rejection.
  • A delete must restate the exact name in the card. Check that it matches.

Results and the record

  • Success, partial success and failure look different: a partial result names the steps that ran and the one that failed, and what to do next.
  • Where a change cannot be re-read, the result says “submitted, not re-verified”.
  • Every message, tool call, card and decision is recorded in a session transcript with secret-shaped values removed; Microsoft’s own audit logs show the same changes under ChatAdmin’s identity.
  • When something goes wrong — a refusal by rule, a missing permission, a throttled call — the answer names the reason in plain words; none of them can cause a change by itself.

Documentation that does not exist yet

So this page cannot over-promise by omission: there is no downloadable manual, no public API reference (there is no public API), and no integration guide, because no integration exists yet. There is no self-service onboarding guide, because there is no self-service sign-in yet. The operator documentation for connecting an environment exists and is shared with evaluators.

When one of these gaps closes, the material will be linked from this page. Until then, a question this page does not answer goes to support@neopiq.ai — hours and the response target are on the support page.
