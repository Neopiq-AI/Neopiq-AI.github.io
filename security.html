Security

ChatAdmin reads your Microsoft Entra, Microsoft 365, Microsoft Azure, Microsoft Power Platform, Microsoft Intune and Microsoft Defender environment with your own Microsoft rights; in customers’ tenants it makes no changes. This is how it stays under your control.

Signing in and connecting

  • You sign in with your Microsoft work account, identity scopes only. ChatAdmin learns your name, sign-in name and tenant id, and shows them on every card.
  • Signing in asks for no administrative access; nothing in your tenant is read or changed. The sign-in token is verified once and discarded.
  • An organisation with a ChatAdmin plan uses it in its own tenant; without a plan you see the plans.
  • To connect your organisation, a Global Administrator accepts Microsoft’s consent for the permissions ChatAdmin uses to read; some areas ask for their own consent the first time you use them. Nothing is installed, and no Neopiq key or secret is kept in your tenant.
  • ChatAdmin then reads with your own Microsoft rights, never more. Changes are not open for customers yet; when they open, your own sign-in approves each one.

A person approves every change

In your tenant ChatAdmin reads and explains today. Changes are not open for customers yet: for a change, ChatAdmin gives you the steps in the Microsoft admin center. When changes open, each one follows the rules ChatAdmin already applies in Neopiq’s own environment:

  • Reads run at once. Every change stops at an Approve / Reject card naming the area, the environment, every step and the checks it ran.
  • A person approves. Nothing is approved by software; an automated check may only reject.
  • Unanswered for five minutes, a card declines itself.
  • Each card is bound to its environment, which is read again at approval: if it changed, the approval is refused.
  • After each step the object is read back from Microsoft, and the result reports that state.

What it reads, and what it never does

It reads directory objects, licences, sign-in error codes, Conditional Access policies, mailbox sizes and permissions, Teams and SharePoint membership, usage reports, Azure resources and costs, Power Platform environments and Copilot Studio agents, Intune information and Microsoft Defender incidents and alerts, within the rights of the person who asks. In customers’ tenants it only reads. Some Microsoft permissions it asks for (Azure, Power Platform, Dataverse, and Files.Read.All and Sites.Read.All in Microsoft 365) are not limited to reading; ChatAdmin’s code uses them only to read and never reads file content.

It never:

  • Read the body of a message, a calendar entry, a chat or a file
  • Create a client secret or password, or read a secret out of a vault
  • Assign Global Administrator from chat, or grant Owner in Azure
  • Forward mail outside your organisation, or delete a mailbox, team, site or file
  • Change Conditional Access, authentication methods, domains or tenant settings
  • Act in your tenant between your turns: nothing reads or changes it on a schedule

Data

  • Conversations (requests, answers, cards, decisions) are kept as transcripts in Neopiq’s own Microsoft Azure storage in Switzerland North, with secret-shaped values removed.
  • What ChatAdmin reads goes to the language model of Anthropic, which processes it in the United States; anything that looks like a key or password is blanked first.
  • A daily job deletes transcripts and event logs older than 90 days; everything of an organisation that leaves is deleted on request.
  • This website sets no cookies and tracks nothing; pages with a sign-in action send one request without cookie or identifier to start ChatAdmin.

Neopiq holds no security certification: no SOC 2 report, no ISO 27001. Report a vulnerability to contact@neopiq.ai with a subject starting SECURITY.
