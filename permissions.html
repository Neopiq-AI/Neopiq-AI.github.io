What ChatAdmin can read and change, area by area, from the code that ships

Most tools that look at a Microsoft estate are read-only and their permission pages are short. ChatAdmin creates and changes real objects in Microsoft Azure, Microsoft Entra, Microsoft 365 and Microsoft Power Platform, so this page works harder: for each area, the identity it acts with, what it reads without a card, what it changes behind one, and what it never does. Reads run at once; every change waits for a person; an unanswered card declines itself after five minutes. The identities below are those of the Neopiq-operated environment today; in your own organisation the identity is you.

In your own organisation: your rights, narrowed, never widened in development

When your organisation is connected, the identity is you: ChatAdmin obtains access to Microsoft for each request through Microsoft’s supported delegated mechanisms and acts with the signed-in person’s own Microsoft rights — Microsoft 365 and Microsoft Entra first; Microsoft Azure and Microsoft Power Platform follow the same rule, and if one of Microsoft’s interfaces requires a different supported mechanism this page will say so for that area. Microsoft decides what those rights allow; the tables on this page are the product’s own ceilings on top of that, and neither a Neopiq subscription nor a ChatAdmin setting adds a right Microsoft has not given. Your organisation can narrow further, per person: Observe (reads only — every change card is refused with the reason), Standard (the person’s full Microsoft authority within the areas you have enabled) or Custom (areas set to allowed, read only or blocked through ChatAdmin, without touching Microsoft roles). Every operation carries a risk class that is the same in all four areas — normal, approval required, high, extreme — and the confirmation grows with it: the exact transaction on a card; a typed confirmation of the target’s name for deletions, removals of access and role or credential changes; a fresh sign-in for tenant-wide changes and for changes to ChatAdmin’s own control plane. No Neopiq key is issued to a customer organisation; your own sign-in is the approval, bound to the one transaction on the card. Microsoft 365 and Microsoft Entra are the base; Microsoft Azure and Microsoft Power Platform are added when you use them. The model in full.

The approval gate, the same in every area

Before any change in the tables above runs, ChatAdmin shows a card: the area, the environment, the action and every parameter with secrets masked, the pre-checks it ran, and a five-minute countdown. Then it waits. In the Neopiq-operated environment the human answers with that area’s approver key, and the decision is recorded with the signed-in person who gave it; in your own organisation your own Microsoft sign-in is the approval and no key exists in development. The coordinating layer holds no key and cannot answer a card. If nobody answers within five minutes, the change is declined — the gate fails closed, never open, and there is no auto-approve of any kind in the product. A plan card covers up to twelve steps with one decision; the steps run in order and stop at the first error. Read-only questions do not pass through the gate, so looking around never generates approval fatigue.

Stated before you find it

  • The approver key proves possession, not identity. It is the mechanism of the Neopiq-operated environment, where the signed-in person who forwarded each decision is now recorded alongside it. It is not the customer mechanism: in your own organisation there is no key, and the signed-in person’s own approval is bound to the transaction. in development
  • The Azure identity holds Contributor on the subscription it operates, which is broader than the table requires; a narrower role per deployment (Reader for a read-only evaluation) is a deploy-time switch.
  • Some Power Platform changes have not yet run live. They are built and tested against a simulated tenant; the product says so in its answer, and this page labels them.
  • Nothing here is an uptime, support or availability commitment. ChatAdmin runs in a Neopiq-operated environment for evaluation today.
